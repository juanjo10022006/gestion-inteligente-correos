## Acceso y sesiones — detalles de ADR-08

- `POST /api/v1/users` crea una cuenta habilitada o deshabilitada, siempre pendiente de activación. Entrega la credencial solo en esa respuesta, con `Cache-Control: no-store`; nunca la devuelve en consultas. Si se pierde o vence, el administrador usa `POST /api/v1/users/{username}/activation-credential`: genera otra, invalida la anterior y audita sin secreto. Solo se permite en cuentas pendientes; no restablece contraseñas activadas.
- Nuevos identificadores: 1–64 caracteres ASCII alfanuméricos o `._-`, sin espacios; unicidad exacta y sensible a mayúsculas. No se normalizan ni renombran usuarios existentes.
- `GET /api/v1/users` devuelve únicamente identificador, rol, estado habilitado/activado y fecha de creación, con paginación. `PATCH /api/v1/users/{username}` actualiza rol y estado; requiere administrador y no permite degradar ni desactivar la propia cuenta. No elimina usuarios.
- Activación exige cuenta habilitada, credencial correcta y no vencida. Al consumirse se eliminan su hash y vencimiento; la nueva contraseña no se devuelve ni se audita. Las cuentas CLI sin marca `activated` conservan su comportamiento y contraseña anterior, aunque sea anterior a la política; no se migran.
- Un cambio real de rol o estado incrementa `authVersion`: las sesiones anteriores quedan inválidas inmediatamente y no reaparecen al rehabilitar la cuenta. La autorización consulta siempre el usuario actual. Las sesiones anteriores sin versión se interpretan como versión cero.
- `POST /api/v1/auth/logout` revoca solo la sesión presentada; React borra el token de memoria tras confirmación del servidor o 401. Si falla la red, ofrece reintentar sin afirmar que el token quedó revocado. No se usa almacenamiento persistente del navegador.
- Las sesiones nuevas usan `validUntil` para autorización y el índice TTL existente de `expiresAt` para limpieza. Mientras hay eventos pendientes no se programa el TTL; tras publicarlos se copia `validUntil` a `expiresAt`. Las sesiones antiguas sin `validUntil` siguen usando `expiresAt`. Así, una caída de auditoría no borra su intención pendiente, sin extender el permiso de acceso.
- Cuentas y sesiones reutilizan la entrega persistida de auditoría y `audit_events`: creación, activación, modificación, login y logout. Estos eventos tienen `messageId=null`, actor y snapshots de datos públicos permitidos; nunca incluyen contraseña, credencial temporal, token, digest ni sal. Se recuperan al arrancar o consultar auditoría global.
- La CLI se conserva como herramienta local de bootstrap; las nuevas altas por consola también generan un evento de creación con actor `SISTEMA`, sin alterar las cuentas preexistentes.
- Los errores de validación de acceso no reflejan valores recibidos. HTTPS sigue siendo obligatorio fuera del entorno local. Los permisos MongoDB de mínimo privilegio y la limitación de intentos siguen siendo endurecimiento pendiente; no se agregan dependencias ni infraestructura en esta intervención.

## Publicación después del commit y límites

Creación/renovación/activación/login/logout conservan éxito si su cambio ya se persistió pero falló la publicación de auditoría; guardan intención y emiten `X-Audit-Status: pending` cuando disponen de respuesta explícita. Los reintentos de publicación no duplican eventos. Esto no evita una pérdida de respuesta de red: la recuperación de una credencial no recibida es renovación administrativa, nunca consulta del secreto anterior.

No debe extrapolarse ese comportamiento a mensajes o a `create_user`: su publicación estricta puede devolver error después de persistir. La API de mensajes no tiene clave pública de idempotencia; `revision` protege actualizaciones, no impide registrar dos veces la misma solicitud. Véanse defectos y evidencias del [plan](PLAN_Y_RESULTADOS_PRUEBAS.md).

La [evaluación IA](09_evaluacion_final_ia.md) es la referencia de versión y cifras, no las cadenas históricas de modelos. La seguridad del bundle depende de origen confiable; un checksum junto a un archivo sustituido por un atacante no acredita autenticidad.
